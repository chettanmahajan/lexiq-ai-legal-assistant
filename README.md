# LexIQ

A small legal research assistant for Indian law. Ask a question in plain English, and LexIQ pulls the relevant passages out of the bare acts (Constitution, IPC, CrPC) and writes back a structured answer.

It runs locally with Streamlit. Retrieval is done with ChromaDB + sentence-transformers, and the actual answer is generated by a Groq-hosted Llama model.

> **Heads up:** this is built for study and quick reference, not for real legal advice. Always check anything important against the primary source (or an actual advocate).

## Why I built this

The Indian bare acts are huge, and finding the section you actually need usually means scrolling through a 500-page PDF. I wanted something where I could just type "what's the punishment for theft under IPC?" and get back the relevant sections with a readable explanation. So LexIQ keeps the PDFs local, embeds them once, and answers from that corpus instead of making things up.

## How it works

The flow is pretty standard RAG:

1. `ingest.py` reads the PDFs in `docs/`, splits them into ~1000-char chunks, embeds each chunk with `all-MiniLM-L6-v2`, and stores everything in a local Chroma database.
2. When you ask a question, the app embeds it, grabs the 3 closest chunks from Chroma, and stuffs them into the prompt as context.
3. Groq (`llama-3.1-8b-instant`) writes the final answer using only that context, formatted into sections like definition, relevant sections, key elements, and a plain-English summary.

Because answers are grounded in the retrieved text, the model is told to say "not enough info in the context" rather than guess when the corpus doesn't cover something.

## Getting started

You'll need Python 3.11+ and a free Groq API key ([grab one here](https://console.groq.com/keys)).

```bash
git clone https://github.com/chettanmahajan/lexiq-ai-legal-assistant.git
cd lexiq-ai-legal-assistant

python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
```

Then set up your key:

```bash
copy .env.example .env         # Windows  (use cp on macOS/Linux)
```

and put your key in the new `.env`:

```env
GROQ_API_KEY=your_key_here
```

Build the vector store from the PDFs (this only needs to run once, and it downloads the embedding model the first time so give it a minute):

```bash
python ingest.py
```

That creates `chroma_db_legal_bot_part1/`, which is gitignored on purpose — there's no point committing a generated database.

Finally:

```bash
streamlit run app.py
```

and open http://localhost:8501.

## Things you can ask

```text
What is the punishment for theft under IPC?
What are the fundamental rights under the Constitution of India?
What happens after an FIR is filed?
```

It only knows what's in the corpus, so questions about, say, tax law won't get a useful answer until you add those documents.

## Adding your own documents

Drop a PDF into `docs/`, add its path to the `PDF_FILES` list in `ingest.py`, and re-run `python ingest.py`. Scanned/image-only PDFs won't parse well since there's no OCR step.

## What's in here

```text
.
├── app.py            # Streamlit UI
├── lexiq.py          # retrieval + answer generation
├── ingest.py         # builds the Chroma vector store from the PDFs
├── prompts.py        # system + answer-format prompts
├── docs/             # the bare-act PDFs
├── .streamlit/       # Streamlit config
├── requirements.txt
├── pyproject.toml
└── .env.example
```

Current corpus: Constitution of India, Indian Penal Code (1860), and the Code of Criminal Procedure.

## Known limitations

- Answers are only as good as the corpus — it can't tell you about laws it hasn't ingested.
- No OCR, so image-only PDFs are a no-go.
- The 8B model is fast but not infallible; double-check anything that matters.
- This is not legal advice. Said it twice now because it's worth repeating.
